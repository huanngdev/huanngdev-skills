# Monorepo (Turborepo + Bun + VoidZero toolchain)

Docs: hd-index docs sources (Turborepo, Bun, Oxc, tsdown, Vite / Vitest).

## Toolchain (prefer VoidZero / Oxc tools everywhere)
| Job | Tool |
|---|---|
| Runtime, package manager, scripts | Bun |
| Task runner | Turborepo |
| Lint | oxlint with `--type-aware` (+ `oxlint-tsgolint`), no ESLint |
| Format | oxfmt (no Prettier) |
| Bundle / dev server | Vite; Next.js only if the project chose it |
| Test | Vitest, always run as `bun --bun vitest run` (Bun APIs available in tests) |
| Package build | tsdown |
Use the full Oxc/Vite ecosystem even where tools are beta; prefer them over alternatives.

## Layout
```
apps/<app>         # deployable: web, api, worker, …  (each has its own .env + .env.example)
packages/shared    # code shared by apps: contracts, Zod schemas, types, utils
packages/<domain>  # shared domain/infra code (db, auth, ui, …)
packages/config    # tsconfig presets, oxlint presets, oxfmt config, vitest base, tsdown base
```
Root `package.json`: `"private": true`, `"packageManager": "bun@<version>"`, `"workspaces": ["apps/*", "packages/*"]`. Root deps = repo tooling only (`turbo`, `oxlint`, `oxlint-tsgolint`, `oxfmt`, `tsdown`, `vitest`, `typescript`).

## Internal packages: compiled with tsdown
Every package in `packages/` (except `packages/config`) builds with tsdown (Rolldown + Oxc): fast rebuilds, errors caught at build time, plain imports for apps.
```json
{
  "name": "@<scope>/shared",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "dev": "tsdown --watch",
    "build": "tsdown",
    "check-types": "tsc --noEmit",
    "lint": "oxlint --type-aware --deny-warnings",
    "test": "bun --bun vitest run"
  }
}
```
```ts
// tsdown.config.ts
import { defineConfig } from "tsdown";
export default defineConfig({ entry: ["src/index.ts", "src/server.ts", "src/client.ts"], dts: true, exports: true });
```
- `exports: true` makes tsdown write the `exports` map into package.json (`dist/*.mjs` + `.d.mts`). Don't hand-edit it; add an entry point in `tsdown.config.ts` instead.
- tsconfig preset for packages enables `isolatedDeclarations`: exported functions need explicit return types, and declarations are generated by Oxc (fast). A missing type fails the build.
- Apps depend with `"@<scope>/shared": "workspace:*"` and import `@<scope>/shared` or `@<scope>/shared/server` — never `src/` or `dist/` paths.
- In dev, `bun run dev` builds packages once, then `tsdown --watch` rebuilds on save while apps run.
- Separate server-only and client-safe entry points so bundles stay clean.
- `packages/config` is the exception: JSON presets + config files loaded by tools, no build.

## turbo.json baseline
```json
{
  "$schema": "https://turborepo.dev/schema.json",
  "ui": "tui",
  "cacheMaxSize": "10GB",
  "cacheMaxAge": "7d",
  "tasks": {
    "build": { "dependsOn": ["^build"], "inputs": ["$TURBO_DEFAULT$", ".env*"], "outputs": ["dist/**"] },
    "dev": { "dependsOn": ["^build"], "cache": false, "persistent": true },
    "lint": { "dependsOn": ["^build"] },
    "check-types": { "dependsOn": ["^build"] },
    "test": { "dependsOn": ["^build"], "outputs": ["coverage/**"] }
  }
}
```
- `ui: "tui"`: one terminal; pick an app/package task in the task list to see its logs and interact with it. Don't add per-app terminal scripts.
- `cacheMaxSize` / `cacheMaxAge`: always set. Override per machine with `TURBO_CACHE_MAX_SIZE` / `TURBO_CACHE_MAX_AGE`. No remote cache.
- `^build` on `dev`/`lint`/`check-types`/`test`: dependents always see fresh `dist` types.
- Add framework outputs per app (e.g. `.next/**`, `!.next/cache/**`) in that app's `turbo.json` or a `app#build` task.
- Every env var a task reads goes in that task's `env` (or `globalEnv`), or cache hits will be wrong.

## Root scripts
```json
"dev": "turbo run dev",
"build": "turbo run build",
"lint": "turbo run lint",
"check-types": "turbo run check-types",
"test": "turbo run test",
"format": "oxfmt -c packages/config/oxfmt.json",
"format:check": "oxfmt --check -c packages/config/oxfmt.json",
"check": "bun run format:check && turbo run lint check-types test build"
```
One app: `bunx turbo run dev --filter=<package-name>`.

## Shared code
- Logic, types, schemas, constants or UI used by ≥ 2 apps → move to a package first, then import it. Never duplicate.
- Apps never import from another app. Packages never import from apps.
- Contract changes (API shapes, Zod schemas) start in `packages/shared`.
- Same third-party version across workspaces; use Bun `catalog:` when the repo has a catalog.

## Lint / format / tsconfig / test config live in `packages/config`
```
packages/config/
  tsconfig/base.json, package.json (isolatedDeclarations), vite-react.json, bun.json
  oxlint/base.json, react.json, node.json
  oxfmt.json
  vitest/base.ts
```
- tsconfig: app `tsconfig.json` = `"extends": "@<scope>/config/tsconfig/<preset>.json"` + includes only.
- oxlint: `extends` takes **relative file paths** (not package names). App `.oxlintrc.json` = `{ "extends": ["../../packages/config/oxlint/react.json"] }`. Script `"lint": "oxlint --type-aware --deny-warnings"` (type-aware options go on the CLI, not in nested configs).
- oxfmt: one config for the whole repo, run from the root with `-c packages/config/oxfmt.json`. No `.oxfmtrc.*` in apps.
- vitest: app `vitest.config.ts` = `mergeConfig(base, { … })` importing `@<scope>/config/vitest/base`.
- Need a different rule for one app? Add/adjust a preset in `packages/config`. Never inline rules in an app.

## Adding things
- New app/package: copy the shape of an existing one (package.json fields, tsconfig, `.oxlintrc.json`, vitest config, script names). The workspaces glob picks it up.
- New dependency: install in the workspace that uses it (`bun add <pkg>` inside that folder). Ask before adding (see `hd-index`).
