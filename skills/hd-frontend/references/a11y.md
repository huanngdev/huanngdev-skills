# Accessibility (WCAG 2.2 AA)

- Native elements first (`button`, `a`, `input`, `label`); shadcn/Base UI components keep their semantics — don't replace them with `div`s.
- Every control has an accessible name: visible label, or `aria-label` for icon-only buttons.
- Everything works with the keyboard: logical tab order, Enter/Space activate, Escape closes overlays, focus returns to the trigger after closing.
- Focus is always visible (keep the kit's focus ring; never `outline-none` without a replacement).
- Dialogs/sheets have a title (and description when useful); focus is trapped while open.
- Text contrast ≥ 4.5:1 (3:1 for large text and UI boundaries) in both themes — muted text included.
- Respect `prefers-reduced-motion`: disable non-essential animation.
- Don't convey meaning by color alone; pair with text or an icon.
- Form errors are linked to their field (`aria-invalid`, `aria-describedby`) and announced; don't rely on toasts for field errors.
- Touch targets ≥ 24×24 px; dense layouts still keep this.
- Images have meaningful `alt` (or `alt=""` if decorative).
- `<html lang>` matches the UI language; app shells have a "Skip to content" link and one `<main>`.
- Playwright main flows include an axe check with no serious/critical violations (`hd-core` testing.md).
